# Fixture environment (verification without shared test accounts)

A reproducible local Playarr server with seeded users, household policies and
placeholder media. It replaces the shared live test accounts: nothing here talks
to a regional or production server, and nothing real is in it.

## Bring it up

```sh
scripts/fixtures/up.sh            # idempotent; add --fresh to wipe the database first
node scripts/fixtures/verify.mjs  # calls the API as every fixture user and asserts the results
scripts/fixtures/down.sh          # stop (add --purge to delete all fixture state)
```

Requirements: `cargo` (or set `PLAYARR_SERVER_BIN` to a built `playarr-server`
and `PLAYARR_FIXTURE_NO_BUILD=1`), `node` 20+, `ffmpeg`/`ffprobe`, `curl`.
Run the cargo build inside your usual memory-capped scope on a shared host.
State lives in `.fixtures/` (git-ignored; override with `PLAYARR_FIXTURE_DIR`).

| What | Default | Override |
| --- | --- | --- |
| Server | `http://127.0.0.1:18484` | `PLAYARR_FIXTURE_PORT`, `PLAYARR_FIXTURE_BIND` |
| Source stub (Sonarr, Radarr, Dubarr) | `127.0.0.1:18490` | `PLAYARR_FIXTURE_STUB_PORT` |
| Child schedule window (UTC minutes of day) | `0-1440` | `FIXTURE_CHILD_WINDOW=360-1260` then re-run `up.sh` |

## What is seeded

All users share the fixture-only password in `scripts/fixtures/catalog.mjs`
(public on purpose: the server is loopback-only and holds placeholders).

| User | Role |
| --- | --- |
| `fx-admin` | administrator that may also stream (use `playarr-admin` platform for the admin API) |
| `fx-viewer` | unrestricted viewer |
| `fx-guardian` | unrestricted; guardian of both child profiles; profile PIN `2468` |
| `fx-child` | max rating `PG`, daily schedule window, 90 minute daily budget, unrated blocked, approvals for content and time required, offline TTL 24 h, profile PIN `1357` |
| `fx-child-locked` | as above but an empty schedule: always `outside_schedule`, 30 minute budget |

Media (generated by `media.mjs`, about 4 MB in total, procedural pictures and
tones, 6 seconds each): three films, two series and one dub.

| Title | Rating | Video | Audio | Subtitles |
| --- | --- | --- | --- | --- |
| Test Movie A | PG | H.264 | eng, fra, spa | eng, fra; Dubarr dub `deu` |
| Test Movie B | R | HEVC | eng, jpn | eng |
| Test Movie C | G | H.264 | eng | sidecar `spa` |
| Sample Series 1 | TV-Y7 | S1 and S3 H.264, S2 HEVC (3 seasons: 3, 2, 2 episodes) | eng, fra | eng; plus an unaired episode three days ahead for the calendar |
| Sample Series 2 | TV-MA | H.264 (1 season, 2 episodes) | eng, jpn | eng |

The child therefore sees Test Movie A, Test Movie C and Sample Series 1 only.
Sonarr, Radarr and Dubarr are replaced by `stub.mjs`, which serves the same
HTTP contracts the server's real clients use and registers as three source
instances; the Dubarr stub offers the `deu` dub for Test Movie A (with `Range`
downloads), which appears in the playback audio list as `dubarr-dub-movie-a-deu`.

## Point clients at it

Web client (Vite dev server proxies `/api` to the fixture server):

```sh
cd clients/tv-web
PLAYARR_DEV_API_PROXY=http://127.0.0.1:18484 pnpm --filter @playarr-tv/web run dev
```

Or serve a built web client from the server itself: build it, then
`PLAYARR_WEB_ASSETS_DIR=<dist> scripts/fixtures/up.sh` (restart if running).

Android emulator: the emulator reaches the host's loopback as `10.0.2.2`, so
enter `http://10.0.2.2:18484` as the server address (the app's network security
config allows cleartext) and sign in with a fixture user. A physical
device needs `PLAYARR_FIXTURE_BIND=0.0.0.0` and the host's LAN address; only do
that on a trusted network.

## Which rows it serves

57/114 household controls (`fx-child`, `fx-child-locked`, `fx-guardian`);
196 dub audio picker (Test Movie A); 110 Android PIN switching (guardian and
child PINs, `/auth/lock` and `/auth/unlock`); 185 language filters
(`/api/v1/catalog/languages`); 223 calendar actions (`/api/v1/calendar`);
256 reconnect (`down.sh` then `up.sh` keeps data and sessions); 371 folders
playback and 456 headless playback (`/api/v1/playback/{media_file_id}` returns
an HLS manifest for every fixture file).

## Limits

Artwork is absent (the stub returns no images). The stub does not implement
download or request flows. Folder roots (unsorted folders) are not registered;
add `.fixtures/media` as a folder root through the admin API if row 371 needs it.
