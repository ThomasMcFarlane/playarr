| 9924 | Server: calendar API 5–22 s on a cold request | in_progress | calendar-perf worker | calendar-api-perf | | 2026-10-10 06:00 ICT | Owner report 2026-10-10: a cold calendar took 5–22 s on live (week 8 s, agenda 22 s; a one-day window 0.7–0.9 s is the round-trip floor) and the page showed "The calendar could not be loaded" (client retry shipped in #455). Causes: (1) every cold build loaded the full detail of each work (a query per episode of every series, plus peer availability) and looked up works and availability lag one title at a time: 545 statements for a week and 2369 for 92 days on a generated library, about 15 ms each on live; (2) the cached response was dropped by any live event, so two requests seconds apart were both cold. Fix on branch `calendar-api-perf`: a fixed 11 to 14 statements however many titles, lag cached until an event is stored, invalidation limited to changes the response depends on, identical concurrent builds shared, `X-Calendar-Cache` header. Pinned by `calendar_perf_tests`. Awaiting the integration merge; live re-measure after deploy. |
