- Peer sync no longer waits on its own bookkeeping. The per-peer diff reads `(media_file_id, content_hash)` from a covering index (migration 0083) instead of every column of about 50,000 rows, once instead of twice, and on a pooled read connection instead of inside the shared write transaction. Changes are written in chunks of 2,000 rows so other queued writes commit in between, and two replacements of one peer's snapshot apply in turn. Idle, release build, 50,000-row peer: diff read 1.0 s to 0.16 s, unchanged sync 1.0 s to 0.27 s, 500 changed rows 2.1 s to 0.42 s. Rows stored before the migration are rewritten once on the next sync.
- `GET /api/v1/peer/availability` and the outbound push serve the previous own-availability snapshot (up to 15 minutes old) while one background task derives the next, instead of every caller waiting behind the derivation lock; the derivation reads each work's files in one query instead of one per file.
