## Conventions



- One row per unit of work. Open work lives in the active sections; finished work moves to "Completed work".
- Format: one `## <N>. <Epic name>` heading per epic (N is a unique, stable positive integer: never renumber or reuse one; a new epic takes the highest + 1) and one table per epic, with exactly the header `| ID | Task | Status | Owner | Branch | Depends | ETA | Notes |`. Cells are not padded. A literal pipe inside a cell is written `\|`.
- Status values: `todo`, `in_progress`, `in_review`, `blocked`, `blocked_on_owner`, `done`. A row that is `done` carries its evidence, `won't do` or `won't fix` reason in Notes. A `todo` row is free to pick up; `blocked_on_owner` waits for a decision or an action only the owner can take.
- `Owner` names a concrete session, subagent or tracked task; `Unassigned` means free to pick up. List handoffs with an arrow.
- `Branch` is the git branch doing the row's work when it is known (named in Notes or Owner, or a worktree or open PR matches the row); otherwise empty. Never invent one.
- A task's reference is `<epic>.<task>` (for example `3.9926`); the ID column keeps the bare ID. Name tasks by reference in Depends, Notes, commits, PR titles and bodies, chat and reports.
- `Depends` lists the references (`<epic>.<task>`, comma-separated) of the rows a row waits for. `ETA` is `YYYY-MM-DD HH:MM <timezone>` (an abbreviation such as ICT, or an offset such as +07:00), or empty.
- Rows converted from the former five-column board (`# | Task | Status | Picked up by | Notes`) keep the old free-text status at the end of Notes as `Previous status: ...`.
- Evidence is a PR link, test result or a short live-verification note. Keep long logs in the PR, not here.
- Never record environment data (host names, IP addresses, registries, node names, paths) or real media titles in a row.
- Add or change rows with `tasks.d/<row-number>.md` fragments; the merge train folds them in.
